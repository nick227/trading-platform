# TradeLoom Admin Capability & Content Inventory

Verified against `server/src/routes/adminRoutes.js`, `server/src/middleware/requireAdmin.js`, `server/src/services/adminService.js`, `server/src/services/emergencyStopService.js`, `server/src/jobs/aiStrategyMarketOpenJob.js`, `server/src/jobs/aiStrategyDailyJob.js`, `server/src/services/strategyEvidenceService.js`, and `server/src/services/brokerReconciliationService.js`.

## Operational Scope Taxonomy

Every Admin surface, metric, table row, and action must explicitly declare which of the three platform scopes it reads or mutates:

1. **Customer Activity** — Real user accounts, customer-owned bots, customer orders/fills, and connected customer Alpaca brokerage accounts (paper or live).
2. **Internal Trading** — TradeLoom's dedicated system account (`usr_platform_canonical` / `tradeloom-ai@tradeloom.internal`), its showcase AI paper bot (`bot_canonical_ai_catalyst_momentum`), autonomous research cycles, and public strategy evidence snapshots.
3. **System Infrastructure** — Background worker heartbeats, Alpha Engine market data feeds, database evidence storage footprint, and immutable administrative audit records.

---

## Critical Implementation Findings (Must Govern Copy & UI)

1. **Emergency Stop defaults to Internal Trading, NOT all customers (`emergencyStopService.js`, `adminService.js:894`):**
   - `POST /api/admin/controls/emergency-stop` stores state per-user in `User.riskSettings.emergencyStop` and defaults `targetUserId` to `usr_platform_canonical`.
   - Without an explicit customer `targetUserId`, activating it **only pauses bots and requests cancellation of active orders owned by `usr_platform_canonical` (Internal Trading)** — it does **not** halt customer bots across the platform.
   - Clearing emergency stop (`active: false`) sets `botsResumed: 0`; paused bots stay paused until resumed individually.
   - **UI rule:** Never claim this switch halts all customer accounts unless targeting a specific user; state the exact affected scope (`TradeLoom Internal Trading` vs. a named customer account).
2. **Daily AI Research (`run-ai-research`) does NOT have a side-effect-free dry run (`aiStrategyDailyJob.js:85-126`):**
   - Even when `dryRun: true` is passed, `runAiStrategyDailyJob` executes Stage 2 (`processPendingAiExecutions` — filling queued paper orders) and Stage 5 (`generateStrategyEvidence` — writing DB snapshots) before checking `dryRun` in Stage 3.
   - **UI rule:** Do not expose a "Dry Run" toggle implying read-only simulation until the backend job isolates all side effects.
3. **Market-Open Fills (`run-market-open`) only affects Internal Trading (`aiStrategyMarketOpenJob.js:47`):**
   - Processes `queued` next-open paper executions strictly for `bot_canonical_ai_catalyst_momentum`, not customer bots.
4. **Order Cancellation (`POST /api/admin/executions/:id/cancel`) is database-only (`adminService.js:789`):**
   - Marks non-filled `Execution` rows `cancelled` in MySQL and writes an `ExecutionAudit` + `AdminAuditLog`, but does **not** send a cancel request to external Alpaca REST APIs. Safe for `queued` / internal simulated orders; cancelling an externally `submitted` live broker order in DB alone can introduce broker position drift.
5. **Broker Reconciliation (`reconcile-all`) short-circuits when `simulationConfig().enabled` is active (`brokerReconciliationService.js:168, 285`):**
   - In simulated broker mode, drift checks always return `inSync: true, positionSource: 'simulated'` without calling Alpaca. Live Alpaca order/position reconciliation runs only when external brokerage mode is active.
6. **Overview totals combine Customer Activity and Internal Trading (`adminService.js:39-58`):**
   - `users.total`, `bots.total`, and `executions.total` query all non-deleted rows, which include `usr_platform_canonical` and its bots/orders. UI copy must state "All accounts (includes 1 internal system account)" or distinguish customer vs. internal rows where breakdown data is loaded.
